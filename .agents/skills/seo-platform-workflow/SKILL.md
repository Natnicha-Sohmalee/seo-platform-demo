# SEO Platform Workflow

ใช้กับแพลตฟอร์มที่ E:\seo-platform และ crawler ที่ E:\crawler

## ข้อตกลงการทำงาน

- สื่อสารภาษาไทย กระชับ และให้ขั้นตอนที่ทำตามได้
- โดยปกติให้โค้ดและคำสั่งพร้อมคัดลอกในแชต ผู้ใช้เป็นคนลงมือ
- แก้ไฟล์เองเมื่อผู้ใช้สั่งให้ทำเองอย่างชัดเจน และจำกัดตามงานที่สั่ง
- สิทธิ์แก้ไฟล์ไม่ได้หมายถึงสิทธิ์รันทดสอบ
- ให้ผู้ใช้รันการทดสอบ เว้นแต่ผู้ใช้สั่งให้ช่วยทดสอบเอง
- ไม่เริ่ม build, crawl, browser test หรือเรียก Gemini เอง
- การทดสอบที่ผู้ใช้รายงานว่าผ่าน ให้นับเป็นผลทดสอบจากผู้ใช้
- สรุปแยกให้ออกว่าอะไรเสนอแล้ว ทำแล้ว และตรวจยืนยันแล้ว
- เก็บแผนและรายงานในแชต เว้นแต่ผู้ใช้ขอเป็นไฟล์
- ไม่สร้างงานในบริการภายนอกหรือใช้ subagent โดยไม่ได้รับคำสั่ง

## เมื่อพัฒนาฟีเจอร์

ใช้ข้อมูลที่คุยแล้ว ไม่ถามเรื่องเดิมซ้ำ
ถามเพิ่มเฉพาะสิ่งที่มีผลต่อการทำงานและยังไม่ทราบ

ก่อนให้โค้ด สรุปสั้น ๆ:
- ปัญหาที่ผู้ใช้ต้องการแก้
- พฤติกรรมที่จะได้
- สิ่งที่ยังไม่ทำในรอบนี้
- เงื่อนไขที่ถือว่ารอบนี้เสร็จ

แบ่งงานเป็นรอบเล็กที่ผู้ใช้ลองใช้งานได้ครบเส้นทาง
ระบุงานที่ต้องเสร็จก่อนเมื่อมีความจำเป็น
ทำทีละรอบ และใช้ผลที่ผู้ใช้ส่งกลับมากำหนดขั้นถัดไป

เมื่อให้แก้โค้ด:
- ตรวจโค้ดปัจจุบันและคำแนะนำของโปรเจกต์ก่อนเมื่อเข้าถึงได้
- บอกพาธไฟล์เต็มและจุดที่ต้องแทนอย่างชัดเจน
- ใช้โค้ดแทนเฉพาะส่วน หากไม่จำเป็นต้องเปลี่ยนทั้งไฟล์
- รักษาข้อมูลเดิม และอธิบายหากการเปลี่ยนแปลงกระทบข้อมูล
- ให้ขั้นตอนทดสอบพร้อมผลที่คาดว่าจะเห็น

## เมื่อมีบั๊ก

เริ่มจากอาการ ข้อความผิดพลาด และขั้นตอนที่ผู้ใช้ทำ
ตรวจโค้ดที่เกี่ยวข้องเท่าที่จำเป็น
แยกหลักฐานที่ยืนยันแล้วออกจากข้อสันนิษฐาน

หากหลักฐานไม่พอ ให้ขอเฉพาะข้อมูลที่ช่วยแยกสาเหตุ
แก้ทีละสาเหตุ แล้วให้ผู้ใช้ลองขั้นตอนเดิมอีกครั้ง
ไม่อ้างว่าแก้สำเร็จก่อนมีผลยืนยัน
ไม่ขอรหัสผ่านหรือค่า API key

## ขอบเขตของผลิตภัณฑ์

- รองรับทั้งผู้ใช้ที่มีเว็บไซต์และผู้ใช้ที่กรอกรายละเอียดธุรกิจเอง
- ออกแบบหน้าจอให้ผู้ประกอบการทั่วไปเข้าใจได้
- แยกข้อมูลจากแหล่งอ้างอิง ข้อมูลธุรกิจ และข้อเสนอของ AI
- ไม่แสดงผลตรวจโครงสร้างเป็นการรับรองความถูกต้องของข้อเท็จจริง
- ไม่รับประกันอันดับ SEO หรือการปรากฏในคำตอบ AI
- การโหลดงานเดิมต้องไม่เรียก AI ใหม่โดยอัตโนมัติ
