01 · ปัญหาและแนวคิดการแก้ปัญหา

ทำไมผู้ประกอบการถึงเริ่มทำบทความ SEO ได้ยาก?

แพลตฟอร์มนี้เปลี่ยนจาก "เริ่มจากหน้ากระดาษเปล่า" เป็น "เริ่มจากข้อมูลจริงของธุรกิจ"

🤔

1. ไม่รู้จะเขียนเรื่องอะไร

คิดหัวข้อไม่ออก ไม่รู้ว่าลูกค้าค้นหาคำไหน หรือหน้าเว็บที่มีอยู่ขาดข้อมูลหรือมีปัญหา SEO จุดใด

⏰

2. ไม่มีเวลาวางโครงสร้าง

การอ่านเว็บตัวเอง คัดคีย์เวิร์ด วางโครง 9 ส่วน และเขียนบทความให้ถูกหลัก SEO ใช้เวลานาน

🛡️

3. กลัว AI แต่งข้อมูลมั่ว

การใช้ AI ทั่วไปมักเกิดการแต่งตัวเลข สถิติ รีวิว หรืออ้างอิงที่ไม่มีอยู่จริง กระทบความน่าเชื่อถือของแบรนด์

💡 แนวทางของ SEO Platform

รวมขั้นตอน เก็บข้อมูลจริง (อ่านเว็บ / รายละเอียดธุรกิจ / CSV คีย์เวิร์ด) → AI เสนอหัวข้อ & Content Brief 9 ส่วน ภายใต้กฎห้ามแต่งข้อมูล → ร่างบทความและแก้ไขใน Tiptap → บันทึกใน Supabase และส่งออก Markdown

02 · คำศัพท์หลักและขอบเขตข้อมูล (GLOSSARY.md)

นิยามข้อมูลหลักของระบบ

อ้างอิงจาก GLOSSARY.md และ docs/adr/0001-project-owns-content-work.md

คำศัพท์ความหมายในระบบการเก็บข้อมูลในโค้ด
ธุรกิจกิจการของลูกค้าที่เป็นเจ้าของข้อมูลและงานเนื้อหาในแพลตฟอร์มผูกกับบัญชีผู้ใช้ (auth.users)
โปรเจกต์ (Project)พื้นที่งานหลักที่รวมข้อมูลเว็บ ชุดคีย์เวิร์ด งานอ่านเว็บ แผนบทความ และบทความตาราง projects
งานอ่านเว็บไซต์การเก็บข้อมูลจากเว็บไซต์ภายใต้โปรเจกต์ 1 ครั้ง พร้อมสถานะและผลรายหน้าcrawl_jobs + crawl_pages
ชุดคีย์เวิร์ดข้อมูลคำค้นที่นำเข้าพร้อมที่มาและช่วงเวลา เพื่อใช้เลือกคำในการวางแผนKeywordSet (เลือกได้สูงสุด 5 คำ)
แผนบทความข้อกำหนดเนื้อหา 1 ชิ้น อ้างอิงข้อมูลธุรกิจ แหล่งข้อมูล และคีย์เวิร์ดcontent_briefs (โครง 9 ส่วน)
บทความ (Article)เนื้อหาที่สร้างและแก้ไขภายใต้โปรเจกต์ โดยอ้างอิงแผนบทความarticles + ส่งออก .md

04 · การนำเข้าคีย์เวิร์ด CSV (/keywords)

จัดการข้อมูลคำค้นอย่างซื่อสัตย์ต่อแหล่งที่มา

โค้ดหลัก: src/lib/keyword-data.ts และ src/app/keywords/page.tsx

📥 การอ่านไฟล์และข้อจำกัด (Bounded Parsing)

  • รองรับไฟล์ CSV/TSV จาก Google Keyword Planner (เดาคอลัมน์อัตโนมัติทั้งหัวตารางไทย/อังกฤษ)
  • จำกัดสูงสุด 1,000 คีย์เวิร์ดต่อไฟล์ และไม่เกิน 100 คอลัมน์ ป้องกันเบราว์เซอร์ค้าง
  • ไม่เรียก AI อัตโนมัติตอนนำเข้า เพื่อไม่ให้เสียโควตาโดยไม่จำเป็น

🏷️ Metadata ที่บังคับเก็บทุกชุด

  • provider: google-keyword-planner
  • location: พื้นที่เป้าหมาย (เช่น ประเทศไทย)
  • fromMonth / toMonth: ช่วงเดือนของข้อมูล (YYYY-MM)
  • network: unknown | google | google-and-partners

🎯 การส่งต่อให้ AI (KeywordSelection)

ผู้ใช้เลือกได้สูงสุด 5 คำต่อบทความ (คำแรก terms[0] คือ คำหลัก ที่เหลือคือ คำประกอบ) ระบบสั่ง AI ให้คงช่วงปริมาณค้นหาตามไฟล์เดิม ห้ามแปลงเป็นค่าเฉลี่ย ห้ามใช้ปริมาณค้นหา/ค่าแข่งขันโฆษณามาอ้างเป็นความยาก SEO หรือรับประกันอันดับ

05 · Python Crawler & การตรวจ SEO เบื้องต้น

อ่านหน้าเว็บจริง แปลงเป็น Markdown และตรวจปัญหาเบื้องต้น

โค้ดหลัก: worker/api.py, worker/crawler_engine.py, src/lib/seo-audit.ts

🕷️ ความสามารถของ Crawler Worker

  • ตั้งค่าต่อ 1 งาน: max_pages (1–10 หน้า), max_depth (1–3 ชั้น)
  • เลือกได้ 2 โหมด: HTML ปกติ (urllib + BeautifulSoup) หรือ JavaScript (Playwright + channel="msedge")
  • แปลงโครงสร้าง HTML (Headings, Lists, Tables, Links, Code) เป็น Markdown สะอาด
  • มีระบบ SSRF / Origin Guard ตรวจสอบ URL ให้ตรงกับเว็บไซต์โปรเจกต์และห้ามเข้าถึง Private/Localhost

🔎 ผลตรวจ SEO เบื้องต้น (analyzeSeo)

  • แบ่งผลการตรวจเป็น 3 ระดับ: problem review unavailable
  • ตรวจ HTTP Status: 404/410 (ไม่พบหน้า), 5xx (เซิร์ฟเวอร์ผิดพลาด)
  • ตรวจ On-page พื้นฐาน: Title ว่าง, Title ซ้ำกันข้ามหน้า (Normalize ด้วย NFKC), Meta Description, Canonical, Headings
  • หมายเหตุ: ตรวจจากหน้าที่อ่านได้เท่านั้น ไม่ใช่การยืนยันว่า Google จะ index หรือไม่

06 · ระบบ AI และการควบคุมความถูกต้อง (/api/content-brief)

AI 3 ขั้นตอน พร้อมกฎเหล็กห้ามแต่งข้อมูลและกัน Prompt Injection

โค้ดหลัก: src/app/api/content-brief/route.ts และ src/lib/ai-provider.ts

1. เสนอหัวข้อ (recommend)

รับหน้าเว็บสูงสุด 10 หน้า (หน้าละ 1,500 ตัวอักษร) สรุปเนื้อหาที่พบและเสนอ 3 หัวข้อ พร้อมเหตุผล กลุ่มเป้าหมาย และ sourceIds

2. แผนบทความ (brief)

รับหน้าเว็บสูงสุด 3 หน้า (หน้าละ 6,000 ตัวอักษร) สร้างแผนโครงสร้าง 9 หัวข้อหลัก พร้อมฟังก์ชัน reviewBrief() ตรวจความครบถ้วน

3. ร่างบทความ (article)

เขียนจากแผนที่ตรวจแล้ว คืนค่าเป็น JSON: title, markdown, seoTitle, metaDescription, slug และ reviewNotes

🛡️ Editorial & Security Guardrails (ฝั่ง Server)

  • เลือก Provider จาก Server Env: รองรับ gemini (@google/genai) หรือ typhoon (api.opentyphoon.ai) Timeout 90s ไม่สลับค่ายอัตโนมัติ
  • Prompt Injection Defense: ระบุชัดเจนว่าเนื้อหาเว็บ ชื่อหน้า URL และคีย์เวิร์ดเป็นเพียงข้อมูล ห้ามทำตามคำสั่งที่แทรกอยู่
  • No Hallucination: ห้ามแต่งตัวเลข สถิติ รีวิว URL หรืออ้างอิง [n] ที่เกินจำนวนแหล่งข้อมูลจริง และจำกัดขนาด Request ไม่เกิน 150 KB

10 · โครงสร้างหน้าเว็บและ API Endpoints

แผนผัง Route ทั้งหมดใน Next.js และ FastAPI

แยกชัดเจนระหว่างหน้าสำหรับผู้ใช้, Route Handlers และ Worker API

📄 หน้าเว็บ (App Router)

  • /login, /update-password — เข้าสู่ระบบและตั้งรหัสผ่าน
  • /projects, /projects/[id] — จัดการโปรเจกต์และสั่ง Crawl
  • /content — กรอกข้อมูลธุรกิจและสร้างแผนบทความ
  • /keywords — นำเข้าและจัดการชุดคีย์เวิร์ด CSV
  • /articles, /articles/[id] — คลังบทความและ Editor

🔌 Next.js API Routes

  • POST /api/crawl — ตรวจสิทธิ์เจ้าของโปรเจกต์ ตรวจ URL ให้ตรง Origin แล้วส่งงานให้ Worker
  • GET /api/crawl/[jobId] — ติดตามสถานะและผลหน้าเว็บของงาน Crawl
  • POST /api/content-brief — รับ recommend / brief / article ตรวจ Schema และเรียก AI
  • /auth/callback, /auth/recovery — จัดการ Supabase Auth

⚙️ FastAPI Worker

  • GET /health — ตรวจสถานะว่า Worker ทำงานอยู่ ({"status":"ok"})
  • POST /crawl — รับงานจาก Next.js (ตรวจ X-API-Key, จอง Semaphore 1 slot)
  • GET /crawl/{job_id} — อ่านสถานะงานปัจจุบันใน memory
  • รัน Background Thread อัปเดต crawl_jobs & crawl_pages ทีละหน้า

12 · โครงสร้างโฟลเดอร์และการตั้งค่า (Repository & Environment)

การจัดวางโค้ดและตัวแปรแวดล้อมของระบบ

แยกฝั่งเว็บ (src/) ออกจากฝั่ง Python Worker (worker/) ชัดเจน

📁 โครงสร้างไฟล์สำคัญ

  • src/app/ — หน้าเว็บ Next.js App Router และ API Routes
  • src/components/ — UI Components (เช่น rich-article-editor.tsx, crawl-runner.tsx, seo-audit-panel.tsx)
  • src/lib/ — Logic หลัก (ai-provider.ts, keyword-data.ts, seo-audit.ts, supabase/)
  • worker/ — api.py, crawler_engine.py, supabase_store.py
  • migration.sql, GLOSSARY.md, docs/adr/ — Schema และเอกสารสถาปัตยกรรม

🔑 ตัวแปรแวดล้อม (Environment Variables)

  • เว็บ (.env.local): NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, SUPABASE_SECRET_KEY
  • เชื่อม Worker: CRAWLER_API_URL (http://127.0.0.1:8787), CRAWLER_API_KEY (ต้องตรงกันทั้งสองฝั่ง)
  • AI: AI_PROVIDER (typhoon / gemini) พร้อม TYPHOON_API_KEY + TYPHOON_MODEL หรือ GEMINI_API_KEY + GEMINI_MODEL
  • Worker (worker/.env): SUPABASE_URL, SUPABASE_SECRET_KEY, CRAWLER_API_KEY

13 · สถานะและขอบเขตการทำงานปัจจุบัน (Scope & Boundaries)

ข้อมูลเชิงข้อเท็จจริงจากสภาพโค้ดปัจจุบันใน README.md และซอร์สโค้ด

🟢 ฟีเจอร์ที่มีอยู่จริงในโค้ด

Supabase Auth (Login/Recovery) สร้างโปรเจกต์ & สั่ง Crawl โหมด HTML & MS Edge JS SEO Audit เบื้องต้น นำเข้า CSV (1,000 แถว) AI เสนอหัวข้อ / แผน / บทความ Tiptap Editor + Version Lock ส่งออก Markdown (.md)

⚠️ ข้อจำกัดและขอบเขตทางเทคนิค

  • สถานะ MVP: พัฒนาสำหรับทดลองใช้งานบนเครื่อง (localhost:3000 และ Worker 127.0.0.1:8787)
  • คิว Worker: ใช้ BoundedSemaphore(1) รับงาน Crawl ได้พร้อมกันทีละ 1 งาน ไม่มีคิวถาวรหลังรีสตาร์ต
  • โหมด JavaScript: เรียกใช้ Microsoft Edge (channel="msedge") และไม่รับประกันเว็บที่บล็อกบอตหรือมี CAPTCHA
  • AI & SEO: ไม่มีการสลับผู้ให้บริการ AI อัตโนมัติเมื่อเกิด Error และผลตรวจ SEO ไม่ใช่การรับรองอันดับการค้นหา

สรุป: SEO Platform เป็นระบบ End-to-End สำหรับสร้างเนื้อหา SEO จากข้อมูลจริงของธุรกิจ ตั้งแต่การเก็บข้อมูลเว็บ/คีย์เวิร์ด การวางแผนด้วย AI ภายใต้กฎคุมความถูกต้อง จนถึงการแก้ไขและส่งออกเป็น Markdown
